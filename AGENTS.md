# Mesa Viva — convenciones del proyecto

Arquitectura completa: `docs/ARQUITECTURA.md`. Historias: `claude-loop/prd.json`.

## Stack real (más nuevo que lo que dice la doc)
- **Next.js 16** (App Router, Turbopack), React 19, TypeScript strict, Tailwind v4, alias `@/*` → `src/*`.
- `cacheComponents` está **desactivado** a propósito (modelo de caché clásico). Páginas que lean BD sin usar `cookies()`/`headers()` deben forzar render dinámico (`await connection()` de `next/server`).
- En Next 16 `middleware.ts` se llama **`src/proxy.ts`** (export `proxy`). La doc dice `middleware.ts`: usa `proxy.ts`.
- `LayoutProps` / `PageProps` son tipos globales generados por `next typegen` (el script `typecheck` lo ejecuta).
- **Prisma 7**: config en `prisma.config.ts` (lee `.env` con dotenv), cliente con `@prisma/adapter-pg`.
- Zod 4, jose 6, bcryptjs 3 (trae sus tipos), TanStack Query 5, Vitest 5, Playwright.

## Base de datos (Prisma 7)
- Generador `prisma-client` → `src/generated/prisma` (gitignored; lo regenera `postinstall` / `npm run db:generate`). Tras tocar el schema: `npx prisma generate` (en v7 `migrate dev` **no** genera ni ejecuta el seed).
- Importar el cliente siempre como `import { db } from "@/lib/db"` (singleton en globalThis con `PrismaPg`). Tipos/enums desde `@/generated/prisma/client` (p.ej. `Role`, `OrderStatus`).
- `schema.prisma` no lleva `url`: la conexión está en `prisma.config.ts`.
- El índice único parcial `one_open_order_per_table` vive solo en el SQL de la migración inicial; Prisma no lo conoce. Al abrir una orden, tratar el error de unicidad (P2002) como "ya hay una orden abierta". SQL a mano: `prisma migrate dev --create-only`, editar `migration.sql`, luego `prisma migrate dev`.
- `npm run db:migrate` · `npm run db:seed` (tsx, idempotente) · `npm run db:reset`. Credenciales demo en `README.md`.
- `Setting` guarda strings: `taxRate` 0.19, `pricesIncludeTax` true, `tipRate` 0.10, `currency` COP, `restaurantName`.

## Reglas de dominio
- **Dinero siempre en centavos enteros** (`Int`). Nunca floats; formatear solo en UI con `formatMoney` (`src/lib/money.ts`).
- **El servidor calcula todos los precios** desde `Product`. El cliente solo envía `productId`, `quantity`, `notes`.
- Lógica de negocio en **`src/lib/domain`**: pura donde se pueda y con tests Vitest en `tests/domain`.
- Cuenta: `computeBill(items, { taxRate, tipRate, pricesIncludeTax })` (`@/lib/domain/billing`); opciones desde BD con `parseBillingSettings(await db.setting.findMany())` (defaults seguros). Con `pricesIncludeTax` el IVA solo se desglosa (`total = subtotal + propina`). Propina siempre sobre el subtotal.
- Estado del cliente: `deriveCustomerStatus(order.status, items.map(i => i.status))` → `IN_PREPARATION | SERVED | CLOSED` (orden no OPEN → CLOSED; sin ítems activos → IN_PREPARATION). Etiquetas en `CUSTOMER_STATUS_LABEL`.
- **Server Actions** (`src/app/actions`) son capas delgadas: validan con Zod, autorizan, llaman a `lib/domain`.
- Orden cerrada = inmutable (rechazar si `status != OPEN`).
- **Mutaciones de órdenes** en `@/lib/domain/orders`: `addItemsToOrder({ token, items })` (cliente), `addItemsToOrderByTableId({ tableId, items })` (mesero), `confirmRound(orderId, round)`, `setItemStatus(itemId, status)`, `cancelItem(itemId)`, `closeOrder(orderId, staffUserId, { tipRate? })`. Cada una bloquea la orden con `SELECT … FOR UPDATE`, rechaza si no está OPEN, incrementa `version` y **no publica eventos**: devuelve `{ orderId, tableId, tableNumber, waiterId, version, … }` para que la Server Action publique tras el commit.
- Transiciones de ítem (puras, `canTransitionItem` en `@/lib/domain/order-rules`): PENDING→IN_PREPARATION→SERVED; PENDING/IN_PREPARATION→CANCELLED. `Bill.lines` = `groupBillLines(items)` (producto+precio+nota, sin cancelados).
- **Errores de dominio** (`@/lib/domain/errors`): `OrderClosedError`, `UnavailableProductsError(productIds)`, `InvalidTableError`, `InvalidTransitionError(from, to)`, `NotFoundError(entity)`; todos extienden `DomainError` (`code` + `message` en español apto para UI). En Server Actions: `if (e instanceof DomainError) return { error: e.message, code: e.code }`. La validación de entrada (Zod) también ocurre en el dominio y lanza `ZodError`.
- **Tiempo real = "señal + refetch"**: tras el commit, `pg_notify('mesa_viva', …)` → SSE (`/api/events`) → el cliente invalida su query y vuelve a pedir. Payloads solo con ids/contadores, **nunca precios** ni datos de otras mesas (ver "Tiempo real").

## Tiempo real (MV-005) — "señal + refetch"
- Contrato único en `@/lib/realtime/events` (sin deps, usable en cliente): `REALTIME_EVENTS` (`order.opened`, `order.items_added`, `order.item_status_changed`, `order.closed`, `waiter.called`, `order.unassigned`, `table.updated`), canales `tableChannel(id)` → `table:{id}`, `waiterChannel(userId)` → `waiter:{id}`, `FLOOR_CHANNEL = "staff:floor"`. Payload `RealtimePayload = { orderId?, tableId?, tableNumber?, round?, version?, reason? }` (`reason` = `"assistance" | "bill"`, solo en `waiter.called`, validado contra `CALL_REASONS`); `sanitizePayload` descarta en runtime cualquier otra clave o tipo. **Nunca precios, ítems ni datos de otras mesas.**
- **Publicar** (servidor, `@/lib/realtime/publish`), siempre **después del commit**: en una Server Action, tras `const r = await addItemsToOrder(...)`, `await publishOrderEvent({ tableId: r.tableId, waiterId: r.waiterId, event: "order.items_added", payload: { orderId: r.orderId, version: r.version, tableNumber: r.tableNumber, round: r.round } })`. Reparte a mesa + mesero + `staff:floor` (todo evento de orden debe llegar al salón); sin mesero añade `order.unassigned` al salón. Bajo nivel: `publish(channel, event, payload)` / `publishMany(channels, …)`. **Nunca lanzan** (solo registran): no envolver en try.
- **Bus** (`@/lib/realtime/bus`): un `pg.Client` dedicado por proceso (globalThis) con `LISTEN mesa_viva`, conexión perezosa en el primer `subscribe(channel, fn)`; si la conexión cae reconecta con backoff y re-LISTEN, y entrega `{ kind: "resync" }` a todos los suscriptores. Tests: `ensureConnected()`, `getBusBackendPid()`, `closeBusForTests()` (llamar en `afterEach`).
- **SSE** `GET /api/events`: `?table=<publicToken>` (mesa existente y no INACTIVE) → `table:{id}`; si no, cookie de staff re-leída de BD: WAITER → `waiter:{id}`, ADMIN/CASHIER → `staff:floor`; resto 401. Lógica en `resolveAuthorizedChannel` (`@/lib/realtime/authorize`). Envía `event: ready` al abrir y tras un resync del bus, `: ping` cada 25 s; `event: <nombre>\ndata: <payload JSON>` por señal.
- **Suscribirse** (cliente): `const { connected } = useRealtimeInvalidate("/api/events?table=" + token, [["bill", token]], (event, payload) => …)` de `@/lib/realtime/use-channel`. Invalida las query keys en cada evento y en cada `ready` (al abrir/reconectar). Mostrar "Reconectando…" si `!connected`. Requiere `QueryProvider` (`@/components/providers/QueryProvider`), ya montado en el root layout.

## Server Actions del cliente (MV-006)
- **`ActionResult<T>`** (`@/lib/action-result`): `{ ok: true, data } | { ok: false, error, code, details?: { productIds? } }`. Las acciones nunca lanzan: `try { … return { ok: true, data } } catch (e) { return toActionError(e) }`. `toActionError`: DomainError → su `message`/`code` (UnavailableProducts añade `details.productIds`); ZodError → "Revisa tu pedido: …" (`VALIDATION`, frases en español por campo); desconocido → mensaje genérico + `console.error` (`INTERNAL`).
- **Rate limit** (`@/lib/rate-limit`): ventana deslizante en memoria. `createRateLimiter({ limit, windowMs, now? })` (puro, reloj inyectable) · `getRateLimiter(name, opts)` (globalThis, por proceso) · `enforceRateLimit(limiter, key)` lanza `RateLimitError` (DomainError `RATE_LIMITED`). Tests de integración: `resetRateLimitsForTests()` en `beforeEach`.
- `src/app/actions/order.actions.ts`: `getMenu()` → `MenuCategory[]` (sin categorías vacías, agotados con `available:false`) · `getTableByToken(token)` → `{ id, number, status } | null` · `submitOrder(token, items)` (10/min por token) → `ActionResult<{ orderId, round }>` y publica `order.opened`/`order.items_added` · `getTableBill(token)` → `ActionResult<TableBillView>` · `callWaiter(token, "assistance" | "bill")` (3/min) → mesa `NEEDS_ATTENTION` + `Table.attentionReason` (`ASSISTANCE`/`BILL`) + `waiter.called` con `reason` a mesero + salón.
- Lecturas en `@/lib/domain/queries` (`getMenuData`, `findPublicTable`, `getTableBillData(token, now?)`): la cuenta muestra la orden OPEN (totales con `computeBill`) o la última CLOSED de las últimas 2 h (totales del `Bill`). Mutación de mesa en `@/lib/domain/tables` (`requestWaiter`).
- Los archivos `"use server"` que no importan `next/*` se pueden importar tal cual en Vitest.

## Plano del mesero (MV-010)
- **Motivo de llamada persistido**: `Table.attentionReason` (enum `AttentionReason { ASSISTANCE BILL }`, null salvo en NEEDS_ATTENTION). Mapear con `REASON_TO_DB` / `REASON_FROM_DB` (`@/lib/domain/tables`). Lo pone `requestWaiter`; lo borran `closeOrder` (mesa AVAILABLE) y `acknowledgeTable`. `addItemsToOrder*` **no** pisa NEEDS_ATTENTION (solo pasa a OCCUPIED si la mesa no está llamando).
- **`getFloorForStaff(user)`** (`@/lib/domain/floor`): WAITER → `table.waiterId = me` OR (`table.waiterId` null AND `zone.waiterId = me`); ADMIN/CASHIER → todas; sin INACTIVE; zonas por nombre, mesas por número. Cada mesa: `{ id, number, seats, zoneName, status, attentionReason: "assistance"|"bill"|null, order: { id, pendingCount, inPrepCount, servedCount, lastRound, openedAt (ISO), subtotal } | null }`.
- **`acknowledgeTable({ tableId }, user)`** (dominio, `SELECT … FOR UPDATE` sobre la mesa): NEEDS_ATTENTION → OCCUPIED (hay orden OPEN) o AVAILABLE, borra el motivo; idempotente (`changed: false`). Permitido a ADMIN o al mesero responsable (de la orden abierta o asignado mesa→zona); si no `ForbiddenError` (`FORBIDDEN`, en `@/lib/domain/errors`).
- Server Actions de staff en `src/app/actions/floor.actions.ts`: `getFloor()` y `acknowledgeTable(tableId)` (publica `table.updated` a salón + mesero si cambió). Empiezan con `requireStaff()` y en el `catch` llaman **`unstable_rethrow(e)`** (next/navigation) antes de `toActionError`, para que el redirect a login no se convierta en error INTERNAL. Importan next/*: no se importan en Vitest (testear el dominio).
- UI: `src/app/staff/page.tsx` (server: `getFloorForStaff` + hora del servidor desde un helper fuera del componente, la regla `react-hooks/purity` rechaza `Date.now()` en el render) → `FloorBoard` (`useQuery(["floor"])`, refetch al enfocar y cada 60 s, `useRealtimeInvalidate("/api/events", [["floor"]], onEvent)`), `TableTile`, `Toasts` (`role="status"`, 6 s, máx. 4), `use-sound.ts` (preferencia `mv:staff:sound` con useSyncExternalStore + try/catch; pitido WebAudio, el AudioContext se desbloquea al activar el interruptor). Lógica pura en `@/lib/floor-view` (`tileKind` con prioridad cuenta/llamada > ronda sin confirmar > ocupada > libre, `TILE_LABEL`, `openedLabel`, `toastFor`, `ROLE_LABEL`).
- Estado de mesa = color del borde + etiqueta con icono (nunca solo color): llamadas con franja guindilla llena + botón "Atendido"; ronda sin confirmar franja azafrán (texto tinta); ocupada borde tinta; libre borde discontinuo gris y fondo plato. Pulso único `.mv-pulse` (overlay con `key` que cambia para repetir; `--pulse` = color), solo con `prefers-reduced-motion: no-preference`; el overlay va debajo del enlace/botón (`relative`). La ficha enlaza a `/staff/mesas/[id]` (MV-011).

## Auth de personal (MV-009)
- Cookie `mv_session` = JWT HS256 (jose) `{ sub, role, name }`, 12 h, httpOnly, sameSite lax, secure en prod. Helpers puros en `@/lib/session` (`signSession`, `verifySession`, `sessionCookieOptions`, `sanitizeNextPath`, `SESSION_COOKIE`); no importan Prisma, así que sirven en `src/proxy.ts`.
- `src/proxy.ts` (matcher `/staff`, `/staff/:path*`) solo verifica la firma y redirige a `/staff/login?next=…`; `/staff/login` siempre es accesible. **No basta**: toda página y Server Action de staff empieza con `const user = await requireStaff()` (o `requireStaff("ADMIN")`, `requireStaff(["WAITER","CASHIER"])`) de `@/lib/auth`. Re-lee el `User` de BD, rechaza inactivos (redirect a login) y lanza `UnauthorizedError` si el rol no cuadra; ADMIN pasa cualquier chequeo. `getSession()` = solo cookie, sin BD.
- Login/logout: `login(prevState, formData)` y `logout()` en `src/app/actions/staff.actions.ts` (usar con `useActionState`). Credenciales: `verifyCredentials(email, password)` en `@/lib/credentials` (bcrypt + hash ficticio si no existe el usuario, contra enumeración por tiempo). El `next` del login pasa siempre por `sanitizeNextPath` (solo rutas `/staff…` relativas).

## Administración (MV-012)
- Dominio en `@/lib/domain/admin`: cada función recibe `(actor, raw)`, llama `assertAdmin(actor)` (`ForbiddenError` si no es ADMIN) y valida con Zod con mensajes en español **por campo** (preprocesa strings de FormData: enteros, checkbox "on"/"true", "" → null en ids opcionales). Conflictos (nombre/email/número repetido vía P2002, categoría con productos, mesa con orden OPEN, desactivarse a sí mismo) → `ConflictError(message, field?)` (`@/lib/domain/errors`, código `CONFLICT`).
- **Precios**: `parsePriceToCents("28.000")` → 2800000 (acepta "28000", "$ 28.000", "28.000,50"; rechaza negativos, "28.00", "28,000"); `centsToPesosInput` es la inversa para precargar formularios.
- Mutaciones de zonas/mesas devuelven `FloorChange { tableId?, tableNumber?, waiterIds }` (meseros antes y después) y la acción publica `table.updated` a `staff:floor` + esos meseros (+ la mesa).
- Producto pedido alguna vez: no se borra, se "retira del menú" (`available=false`). Mesa con historial: no se borra, se desactiva (INACTIVE); con orden OPEN ni eso. `rotateTableToken` → nuevo `publicToken` (`newPublicToken()`, 18 bytes base64url).
- **Una sola Server Action** `adminMutate(prev, formData)` (`src/app/actions/admin.actions.ts`) con campo oculto `intent` (`product.create`, `table.rotate`…): `requireStaff("ADMIN")` → handler → publicar → `revalidatePath`. Devuelve `AdminFormState` (`@/lib/admin-form`: `ok`, `message`, `error`, `fieldErrors`, `values` sin contraseñas) vía `toFormState(e, values)`. Nueva operación = nueva entrada en `HANDLERS`.
- UI en `src/components/admin/AdminForm.tsx`: `<AdminForm intent hidden closeOnSuccess>` (useActionState + contexto) con `Field`/`SelectField`/`CheckboxField` (error inline + aria-describedby; re-muestran lo escrito si falla, porque React resetea el form tras la acción), `SubmitButton`, `FormStatus`, `ToggleForm` (dos botones con aria-pressed; envía con el `name/value` del botón) y `Disclosure` (`<details>` para editar/confirmar en línea: nunca `window.confirm`).
- Páginas `/staff/admin/{menu,mesas,equipo,qr}` (layout con sub-nav) llaman `requireAdminPage()` (`@/lib/auth`: otro rol → redirect a `/staff`). `/staff` muestra el enlace "Administración" solo a ADMIN.
- QR: `GET /api/qr/[tableId]` (getSession + rol en BD: 401/403/404) → PNG de `tablePublicUrl(PUBLIC_BASE_URL || origen del request, token)` con `Cache-Control: private, no-store` (el token rota). La hoja imprimible usa variantes `print:` de Tailwind (`print:hidden`, `print:grid-cols-3`, `break-inside-avoid`).

## Detalle de mesa (MV-011)
- **Permisos por mesa**: regla pura `decideTableAction(user, { orderWaiterId, assignedWaiterId }, action)` (`@/lib/domain/permissions`, acciones `view | manage | close`); con BD: `assertCanActOnTable(user, tableId, action)` (`@/lib/domain/staff-table`, lanza `NotFoundError("Mesa")` (también con id no-uuid) o `ForbiddenError`). ADMIN todo; **WAITER** solo si es el mesero de la orden OPEN o el asignado (`table.waiterId ?? zone.waiterId`), y entonces puede todo; **CASHIER** ve y cierra cualquier mesa (cobra) pero **no** cambia ítems ni agrega productos (`manage`). `acknowledgeTable` usa el mismo `isResponsibleWaiter`.
- Mutaciones autorizadas en `@/lib/domain/staff-table` (cada una `(user, raw)`: Zod → assert → dominio de `orders`): `staffConfirmRound`, `staffServeRound` (nuevo `serveRound(orderId, round)`: IN_PREPARATION → SERVED con `servedAt`), `staffSetItemStatus` (solo IN_PREPARATION/SERVED/CANCELLED), `staffCancelItem`, `staffAddItems`, `staffCloseService({ orderId, tipRate })` (fracción 0–1, redondeada a 4 decimales). Lectura: `getTableDetailForStaff(user, tableId, now?)` → `{ table, order (rondas asc con ítems + createdAt/servedAt ISO), totals (computeBill), closedBill (última cerrada ≤ 2 h, solo sin orden abierta), settings, can: { manage, close } }`.
- Server Actions en `src/app/actions/table.actions.ts` (`getTableDetail`, `confirmRoundAction`, `serveRoundAction`, `setItemStatusAction`, `cancelItemAction`, `addItemsForTableAction`, `closeServiceAction`): `requireStaff` → dominio → `publishOrderEvent` (`order.item_status_changed` solo si cambió algo, `order.opened/items_added`, `order.closed`).
- UI `/staff/mesas/[id]`: la página atrapa Forbidden/NotFound y muestra un mensaje (no lanza). `TableDetail` usa `useQuery(["table", id])` + `useRealtimeInvalidate("/api/events", [], onEvent)` filtrando `payload.tableId === id` (con keys vacías el `ready` no refresca: un effect invalida al pasar `connected` a true). Componentes: `RoundTicket` (nota resaltada azafrán, confirmación de cancelar en línea), `AddItemsSheet` (reusa `@/lib/cart`, `NoteField`, `QuantityStepper`, `Sheet`), `CloseServiceSheet` (vista previa con `computeBill` en el cliente; el servidor recalcula), `FinalBill` (se imprime: todo lo demás `print:hidden`). Helpers puros en `@/lib/table-view` (`roundActions`, `itemActions`, `unservedCount`, `parseTipPercent`, `percentLabel`, `formatClock` con zona fija America/Bogota para evitar desajustes de hidratación).
